# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

`sohopay/skills` is the **canonical source for SohoPay agent skills** — Markdown docs that teach AI coding agents (Cursor, Claude Code, Codex) how to integrate with the SohoPay MCP gateway and x402 credit settlement. It is a content + tooling repo, **not an application**. Executable code is zero-dependency Node ESM scripts that validate, generate `llms-full.txt`, and sync the registry bundle.

Delivery is via curl bootstrap (`curl -fsSL …/setup.md`) and the open skills registry (`npx skills add sohopay/skills -g`). The MCP server is the runtime — this repo intentionally ships **no CLI**.

## Commands

```bash
npm run build               # generate:llms-full + sync:bundle
npm run validate            # scripts/validate-skills.mjs — CI guardrails (see below)
npm run generate:llms-full  # scripts/generate-llms-full.mjs — rebuild llms-full.txt
npm run sync:bundle         # mirror root skills → plugins/.../docs/
bash scripts/verify-bootstrap.sh   # full E2E: generate + validate + registry list + optional hosted URL probe
```

Requires Node `>=22`.

## Architecture: how a skill flows through the system

The system has one source of truth (`.well-known/agent-skills/index.json`) that drives everything downstream. Understanding this fan-out is essential before editing:

1. **`index.json`** lists every hosted skill with `name`, `title`, `description`, and `url`.
2. Each skill's **`<name>.md` at the repo root** is the hosted body (e.g. `setup.md`, `spend-and-pay.md`). The filename **must** match the `name` in `index.json`.
3. **`llms-full.txt`** is generated by concatenating every skill body in index order — **CI-generated, never hand-edit it**. Regenerate with `npm run generate:llms-full` or `npm run build`.
4. **`plugins/sohopay/skills/sohopay-integrate/`** is the open-registry package: `SKILL.md` (umbrella) + `docs/` (byte-identical mirror of root skills — **never hand-edit docs/**; run `npm run sync:bundle`).
5. On push to `main`, `.github/workflows/deploy.yml` syncs `.well-known/` and skill files under **`/skills/v1/`** to S3 + CloudFront (`agents.sohopay.xyz`).

### Prod vs staging docs

- **Canonical:** `setup.md`, `mcp-connect.md` — environment table with `{API_BASE}`, `{MCP_URL}`, `{MCP_ORIGIN}`, `{MCP_SERVER_ID}`.
- **Env-preset stubs:** `setup-staging.md`, `mcp-connect-staging.md` — pin staging values and chain to the canonical doc via `{SKILLS_BASE}/…`. Keep stub names for stable URLs.

### Adding or renaming a skill (the critical path)

Because `index.json` is authoritative, adding a skill requires editing it **and** creating the matching root file — the validator enforces the pairing both ways:

1. Add an entry to `.well-known/agent-skills/index.json` with `url` set to **exactly** `https://agents.sohopay.xyz/skills/v1/<name>.md`.
2. Create `<name>.md` at the repo root.
3. Optionally add it to the quick-reference table in the registry `SKILL.md`.
4. Run `npm run build` and `npm run validate`.

## Validation constraints (what CI will block)

`scripts/validate-skills.mjs` fails the build on any of these, so respect them while editing skill Markdown:

- **No localhost / loopback**: `localhost`, `127.0.0.1`, `0.0.0.0` (use `{MERCHANT_BASE_URL}` etc.).
- **No secret-like patterns**: `sk-…` keys, `AKIA…` AWS IDs, PEM private-key headers, `x-soho-service-token:` values.
- **All Markdown links must be absolute** unless they point at `github.com/sohopay` or use `{SKILLS_BASE}`.
- **No hardcoded `agents.sohopay.xyz`** outside the SKILLS_BASE HTML comment header — use `{SKILLS_BASE}`.
- **curl must use `-f`** (prefer `curl -fsSL`); never `curl -sL`.
- **`index.json` ⇄ file pairing**: every `url` must be the `/skills/v1/<name>.md` form, and every `<name>.md` must exist.
- **`setup.md` safety scaffolding**: global failure rule, ≥3 STOP gates, "Report to the operator".
- **Env-preset stubs** must declare STAGING and link `{SKILLS_BASE}/setup.md` or `{SKILLS_BASE}/mcp-connect.md`.
- **Bundle drift**: `plugins/.../docs/` must match root after `npm run sync:bundle`.

## Conventions that are locked

- **Hosted hostname is `sohopay.xyz`, never `sohopay.com`.** Canonical endpoints: `docs/endpoints.md`.
- **Registry skill ID is brand-prefixed** (`sohopay-integrate`); hosted files keep generic workflow names.
- Naming conventions table lives in `docs/PLAN.md`; registry notes in `docs/registry.md`.

## SohoPay domain rules to preserve in skill content

1. `borrowerId` is a UUID — never use a wallet address as primary identity. `whoami` often omits `borrower_id`; resolve it as `whoami.borrower_id ?? whoami.principal_id` (human-direct only — in delegated sessions `principal_id` is the agent, not the credit owner).
2. Never hold borrower private keys — the MCP transport carries signatures only.
3. Idempotency: `Idempotency-Key` **or** tool arg `idempotency_key` (required for Cursor/ChatGPT) on write tools.
4. Resolve authorization fresh (`POST /api/v1/auth/authorization-context`) before privileged tools. The borrower token from `request_borrower_token` is short-lived (staging 15 min) and is **not** the auto-refreshed OAuth transport token — re-request it before each spend.
5. x402: prefer **merchant-as-settler** (`X-PAYMENT`); on 202 retry the same header; borrower-direct is `/api/v2/x402`; legacy `/api/v1/x402/v2` sunsets 2027-02-10.
6. `get_signing_status.signature` is `intentSig`; pass `policy_decision_id` into `sign_transaction` for orderRef binding (`spend_intent_id` is not accepted there). `sign_transaction.payload` must be an object, and its `payment_intent` echo supplies the `X-PAYMENT` wire fields.
7. Poll settlement by **`settlement_id`** (not `payment_id`). Base L2 `finalized` ~15–19 min; `available_credit` updates only after `CONFIRMED`.
8. `Mcp-Session-Id` ≠ SohoPay `session_id` / `x-session-id`.
9. **No Node for default setup** — hosted MCP + fetch docs; Node only for optional `npx` install or local MCP server.
