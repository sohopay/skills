# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

`sohopay/skills` is the **canonical source for SohoPay agent skills** — Markdown docs that teach AI coding agents (Cursor, Claude Code, Codex) how to integrate with the SohoPay MCP gateway and x402 credit settlement. It is a content + tooling repo, **not an application**. The only executable code is two zero-dependency Node ESM scripts that validate and build the hosted content.

Delivery is via curl bootstrap (`curl -sL https://agents.sohopay.xyz/skills/setup.md`) and the open skills registry (`npx skills add sohopay/skills -g`). The MCP server is the runtime — this repo intentionally ships **no CLI**.

## Commands

```bash
npm run validate            # scripts/validate-skills.mjs — CI guardrails (see below)
npm run generate:llms-full  # scripts/generate-llms-full.mjs — rebuild llms-full.txt
bash scripts/verify-bootstrap.sh   # full E2E: generate + validate + registry list + optional hosted URL probe
```

There is no build, test, or lint step beyond these. Requires Node `>=22`.

## Architecture: how a skill flows through the system

The system has one source of truth (`.well-known/agent-skills/index.json`) that drives everything downstream. Understanding this fan-out is essential before editing:

1. **`index.json`** lists every hosted skill with `name`, `title`, `description`, and `url`.
2. Each skill's **`<name>.md` at the repo root** is the hosted body (e.g. `setup.md`, `spend-and-pay.md`). The filename **must** match the `name` in `index.json`.
3. **`llms-full.txt`** is generated by concatenating every skill body in index order — **CI-generated, never hand-edit it**. Regenerate with `npm run generate:llms-full`.
4. **`plugins/sohopay/skills/sohopay-integrate/SKILL.md`** is the open-registry package (single umbrella skill `sohopay-integrate`) that links out to the hosted files.
5. On push to `main`, `.github/workflows/deploy.yml` syncs `.well-known/`, the skill `.md` files, and `llms-full.txt` to S3 + CloudFront (`agents.sohopay.xyz`, `us-east-1`) via AWS OIDC.

### Adding or renaming a skill (the critical path)

Because `index.json` is authoritative, adding a skill requires editing it **and** creating the matching root file — the validator enforces the pairing both ways:

1. Add an entry to `.well-known/agent-skills/index.json` with `url` set to **exactly** `https://agents.sohopay.xyz/skills/<name>.md`.
2. Create `<name>.md` at the repo root.
3. Optionally add it to the quick-reference table in the registry `SKILL.md`.
4. Run `npm run generate:llms-full` and `npm run validate`.

## Validation constraints (what CI will block)

`scripts/validate-skills.mjs` fails the build on any of these, so respect them while editing skill Markdown:

- **No localhost / loopback**: `localhost`, `127.0.0.1`, `0.0.0.0`.
- **No secret-like patterns**: `sk-…` keys, `AKIA…` AWS IDs, PEM private-key headers, `x-soho-service-token:` values.
- **All Markdown links must be absolute.** Relative links are rejected **unless** they point at `github.com/sohopay`. Hosted skill bodies reference other skills by full `https://agents.sohopay.xyz/skills/…` URLs, not relative paths.
- **`index.json` ⇄ file pairing**: every `index.json` `url` must be the canonical form above, and every `<name>.md` must exist.

## Conventions that are locked

- **Hosted hostname is `sohopay.xyz`, never `sohopay.com`.** Older planning docs may say `.com`; treat `agents.sohopay.xyz` / `api.sohopay.xyz` / `mcp.sohopay.xyz` (see `docs/endpoints.md`) as canonical.
- **Registry skill ID is brand-prefixed** (`sohopay-integrate`) to avoid collisions; hosted files keep generic workflow names (`setup.md`, `mcp-connect.md`, …).
- Naming conventions table lives in `docs/PLAN.md`; endpoint truth in `docs/endpoints.md`; registry compatibility notes in `docs/registry.md`.

## SohoPay domain rules to preserve in skill content

These are the integration invariants the skills teach — keep them accurate when editing skill bodies:

1. `borrowerId` is a UUID — never use a wallet address as primary identity.
2. Never hold borrower private keys — the MCP transport carries signatures only.
3. Send an `Idempotency-Key` on every mutating financial/on-chain route.
4. Resolve authorization fresh (`POST /api/v1/auth/authorization-context`) before privileged tools.
5. x402: verify before settle; poll confirmation; on-chain idempotency TTL is 72h.
